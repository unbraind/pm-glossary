# Architecture

The durable unit is one native `Glossary` owner item in `glossary/`. Native title and description name the lexicon; related dependencies link consuming tasks. The registered object field `glossary_state` holds all authoritative terminology and idempotency data. Native comments and append-only item history retain attribution and reviewed mutations. No package journal, counter, global registry or local item-path API exists.

State version 1 contains `domain_key`, exact language policy, an explicit scope tree, senses, direct aliases, an empty reserved binding collection and replay receipts. Strict exported schemas validate both normalized submissions and complete stored reads. Native schema registration is extension contribution only; activation never persists a migration. The directory adapter provisions missing native project schema only on explicit creation. It refuses incompatible existing definitions. Unknown versions refuse without rewriting anything. No earlier glossary schema requires migration in this initial release.

The scope graph is a single-root parent tree with unique keys, at most 64 nodes and eight levels. Sense and alias scope references must exist. Resolution checks exact surface and language in the requested scope, then parents, stopping at the first level containing a match. A set of sense IDs deduplicates aliases that point to the same sense; all different senses survive. Candidates sort by stable sense ID. No Unicode normalization, case folding, language fallback, fuzzy inference, timestamps or model ranking is applied. Contrast IDs identify different existing senses; diagnostics can report broken references in older structurally readable records.

Aliases have their own identities, surface, language and scope, and point directly to a sense ID. Alias chains, missing targets and cycles cannot be created. A same-level direct term and an alias to another sense create explicit ambiguity. A parent alias cannot defeat a nearer direct term. Unknown and ambiguous outcomes both abstain, but distinguish absence from a witnessed collision.

Each mutation reads only its authorized aggregate owner. Native `get` returns the selected full document and `item_hash`. The reducer constructs the next complete namespaced object, preserving all peer-owned native fields. `withExpectedItemRevisions([{id,itemHash}], () => client.update(...))` compares under the SDK's native mutation lock; the update includes both the object and an audit comment. Checked receipts must name the owner and have no unchecked expectations. The package never approximates CAS with an unconditional update or its own mutex.

The directory adapter uses the declared custom-field option for persisted project schemas; extension-host dispatch uses its registered field route. Both paths execute native create/update and native revision scopes. Observation callbacks run outside that scope: native scopes advance after their own writes, so nesting an unrelated peer write inside the callback could incorrectly advance the outer expectation. The callback is not an authorization hook or transaction boundary.

Creation requires a caller-owned native ID and uses native create-if-absent. Duplicate-ID recovery validates the stored Glossary schema and the first creation operation/request digest. An unrelated item or different request refuses. Replay keys map to canonical request and committed semantic result digests. Both sides pass the same strict normalizers: stable identifiers and hashes trim; hashes lowercase; lexical surfaces preserve exact Unicode, case and whitespace. JSON object keys sort for hashing; array order remains meaningful. The directory and CLI adapters use the public SDK item-ID normalizer before creation; existing-owner request digests use the canonical ID returned by the native read. Injected providers supply their own identity normalizer or require canonical IDs. Unprefixed and canonical retries therefore share one request identity.

Same key plus identical normalized request returns the original result without appending history, alongside the current observed owner hash. Same key with different content refuses. Commutative additions may retry a lost CAS at most three times, using the original key; a now-owned sense/alias identity refuses. Explicit edits and stale decisions never rebase. Every public read/guard/update/receipt boundary has an interleaving or crash test. Two OS processes exercise the native lock separately. An interrupted result may be committed, not committed, or unknown; read-back by original key converges without duplicate audit events. Native history is not rolled back or repaired.

Limits are 128 senses, 256 aliases, 128 future bindings, 256 replay receipts, 64 KiB current canonical JSON state, 2,000 Unicode code points per definition, and 8 immutable provenance references per sense. This first slice permits zero bindings. Bounds refuse before owner mutation; successful replay keys never evict. Partition a domain or create an explicit successor when capacity is exhausted. The native history can be larger than current state; retention and redaction remain host policy.

Provenance names `{item_id,item_hash,field_pointer,citation_id?}` without crawling or copying source content. A reference pins one item revision, not a coherent multi-item snapshot or freshness verdict. Exact source spans, use-site bindings, evidence freshness adapters and explicit binding revalidation remain the later Feature `pm-glossary-3jep`. `check` reports duplicate alias tuples and broken contrasts, and explicitly reports unknown freshness; invalid scopes and corrupt records refuse with remedies.

The SDK host supplies a PmClient-shaped port, authorization and provider conformance evidence. Kernels use no tracker root, filesystem, Git, shell, network or model. The directory adapter uses the public root-oriented PmClient. The identical public request API accepts injected lifecycle ports, but an arbitrary provider is not certified by method presence. Missing native CAS/create-if-absent guarantees refuse `backend_unsupported` before storage access. Additional provider certification remains blocked on upstream issues 1399, 1587 and 1588 and owner-supplied conformance evidence. No hosted backend or database is contacted by this package.

TOON and JSON are scoped native renderer contributions for the same versioned typed envelope. SDK `fitOutputEnvelope` measures both exact serializations, including newline framing and its self-accounting receipt. Mandatory metadata, candidate IDs and definitions, safety warnings, source revisions and ambiguity witnesses never truncate. Optional excerpt omission is unnecessary in this slice because no source excerpts are emitted. The default is 1,600 estimated tokens, with a 32 KiB hard ceiling per envelope. Packets page whole resolution rows, default 20, max 100. Opaque cursors use the public SDK codec and bind native owner revision, query digest, offset, denominator and projection; changing any query component or state refuses instead of mixing versions. Refusals use the same output envelope and native `exit_code` contract, with bounded diagnostic metadata and a concrete remedy.

Privacy checks happen before any submitted content enters history. The public SDK secret scanner detects credential shapes. Additional input guards reject private home paths, email addresses, control/bidi sequences, malformed Unicode, executable expressions, prototype keys, cyclic values and excess nesting/size. Ordinary technical vocabulary and instruction-like prose remain inert data. Stored reads validate schema without retroactively imposing new submission policy; serializers escape unsafe historical control bytes. The local collaboration trust boundary does not authenticate authors or add access control.

Verification uses real non-git SDK trackers, not SDK storage mocks. A seeded independent scope oracle compares 500 random operation sequences with SDK read-back, including exact whitespace, relationships and older replays. Public corpus definitions are manually reviewed gold data authored independently from the resolver, pinned to source commits and passage digests. This is an explicit declared-scope correctness sample, not an independent human review or a universal language claim. Instrumentation inventories every emitted production module and counts independent statements/branches/functions/lines. Packed acceptance captures one archive and exercises it with npm, Bun, npx and bunx with Git absent. Development/release tooling uses Git independently from runtime behavior.

The host validates native output controls before package parser overrides. Its only command declaration, `read_output?: { row_keys: readonly string[] }`, opts read-only handlers into generic shaping; it does not supply a mutation cost capability or a producer cursor-consumption port. Native cursor replay also applies outside the handler and conflicts with aggregate-owned pagination. Feature `pm-glossary-yrza` records this release blocker, the inspected signatures and upstream search. The package therefore exposes explicit `--budget` and `--cursor` fallback flags, retains the host renderer and SDK fitter, and never shadows native flags or marks writes read-only. Packed tests assert host-native refusal before mutation and successful fallback paging. Exact native-control compliance is not claimed.
